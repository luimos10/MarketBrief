# Frontend Design For Market Brief

Use this skill only when the request changes the visual interface or user experience.

## Product Context

Market Brief is a pre-market report for traders. Its HTML is generated by
`modules/delivery.py` and delivered locally or through Telegram. It presents
time-sensitive, information-dense financial data: market bias, asset cards,
macro context, technical levels, and operating plans.

The established visual language is a compact dark interface with CSS variables
for surfaces, text, and market states. Preserve it unless the request explicitly
calls for a redesign.

## Workflow

1. Inspect `modules/delivery.py` and a current generated `output/brief_*.html`
   before changing visual code.
2. Identify the relevant generated markup, CSS rules, and any JavaScript that
   produces dashboard content or charts.
3. Make the smallest change that satisfies the request. Keep HTML generation
   deterministic and compatible with the project's dependency-free renderer.
4. Preserve existing report content and meaningful values. Never replace real
   market data with placeholder copy merely to make a layout look complete.
5. Generate an HTML brief with `python brief.py --html --no-open` when the
   required environment is available, then inspect the result.

## Design Principles

- Establish clear scan order: session/status, market bias, primary assets,
  context, then detailed analysis.
- Optimize for analysts reading a dense report, not for a generic marketing
  dashboard. Use restrained spacing and avoid decorative panels.
- Keep important trading data readable at a glance: ticker, price, change,
  bias, confidence, key levels, and risk state.
- Use semantic market colors consistently: bull for constructive/positive,
  bear for negative/risk, neutral for mixed or inconclusive, and accent only
  for actions or intentional emphasis.
- Do not communicate a state only by color; include visible text, iconography,
  or labels as appropriate.
- Keep contrast high on the dark background and preserve legible muted text.
- Prefer CSS grid and flexible sizing over fixed pixel layouts.
- Preserve the existing typography stack unless there is a concrete reason to
  change it.

## Responsive And Accessibility Requirements

- Test layouts at narrow mobile widths and desktop widths.
- Ensure tables either remain usable on narrow screens or have an intentional
  horizontal scrolling treatment; never silently clip data.
- Do not rely only on hover to reveal essential information.
- Preserve semantic headings and their logical hierarchy.
- Ensure keyboard focus remains visible for any interactive element.
- Keep charts and visual indicators accompanied by a text label or value.

## Boundaries

- Do not modify market calculations, scoring logic, data collection, prompts,
  or Telegram content unless the requested UI change requires a minimal related
  change.
- Do not add a frontend framework or build step to this Python-generated HTML
  report without explicit approval.
- Do not edit generated files in `output/` as the source of truth; edit the
  generator in `modules/delivery.py`.

## Completion Report

State which visual areas changed, the responsive behavior considered, and the
command used for verification. Mention any visual check that could not be run.
